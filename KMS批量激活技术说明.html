1. 什么是 KMS

KMS（Key Management Service，密钥管理服务）是微软为批量授权客户提供的本地激活方式。 它允许一个组织在内网中运行一台（或多台）KMS 主机（激活服务器），让同网的客户端操作系统与 Office 自动完成激活，无需每台都连微软、也无需逐个输入零售密钥。

它和零售激活（数字许可证 / 产品密钥）、MAK（多次激活密钥）并列，是三种主要激活方式之一， 专门面向中大型组织的运维场景。

📌 KMS 本身完全合法，是微软官方技术；问题只出在"用非授权主机去激活正版未授权副本"这一行为上。

2. 工作原理

  • 角色分工：KMS 主机持有 KMS Host Key（CSVLK）；客户端持有 GVLK（通用批量授权密钥），自动向主机请求激活。
  • 激活阈值：Windows 客户端需达到 25 台才触发激活；Office 需 5 台。低于阈值时仅进入"宽限期"，不影响试用。
  • 有效期与续期：激活后有效期 180 天；客户端每 7 天主动回连主机续期，联网正常则"无感永久有效"。
  • 自动发现：主机通过 DNS 发布 _vlmcs._tcp 的 SRV 记录，客户端无需手填地址即可发现主机。
  • 无需公网：KMS 走内网即可，主机本身也只在首次安装 CSVLK 时需要连一次微软。
📌 GVLK（客户端密钥）是公开文档，已另页整理；CSVLK（主机密钥）则需从 VLSC 批量门户获取，不公开。

4. 企业如何合法自建 KMS

持有微软批量许可协议（如 Enterprise Agreement、Open Value、教育授权等）的组织，可按下列步骤搭建内网 KMS：

  • ① 获取 CSVLK：登录 VLSC（Volume Licensing Service Center），下载对应产品的 KMS 主机密钥。
  • ② 安装主机：在一台 Windows Server 上安装批量激活服务（VAMT 或角色），用 slmgr /ipk <CSVLK> 装入主机密钥并激活主机自身。
  • ③ 发布 DNS：在内部 DNS 创建 _vlmcs._tcp SRV 记录指向该主机，客户端自动发现。
  • ④ 客户端就绪：客户端装入 GVLK（多数批量镜像已内置），到达阈值后自动激活、180 天自动续期。
📌 这套流程全程使用你方自有合法授权，是 KMS 的合规用法。公共/第三方 KMS 主机不在你的授权范围内，连接它们即超出许可。

5. 常用 slmgr 命令（合法运维用）

slmgr.vbs 是 Windows 内置的授权管理脚本（需管理员 CMD/PowerShell）。下列命令用于自有授权的 KMS 环境排障：

slmgr /ipk <GVLK>复制 slmgr /skms kms.your-domain.local复制 slmgr /ato复制 slmgr /dlv复制 slmgr /upk复制
命令作用
slmgr /ipk <GVLK>安装指定的 GVLK 客户端密钥
slmgr /skms <host>手动指定 KMS 主机地址（不依赖 DNS 发现时）
slmgr /ato立即触发激活尝试
slmgr /dlv显示详细激活与授权信息（含 KMS 计数）
slmgr /upk卸载当前产品密钥
⚠️ 切勿将上述命令与"公共 KMS 主机地址"拼接使用于非授权副本——这属于规避授权，违反软件许可协议。

6. 为什么不要连接来路不明的公共 KMS

  • 法律风险：用非授权 KMS 主机激活未授权副本，违反微软软件许可条款，属授权规避；企业或机构使用可能面临合规审计与赔偿。
  • 安全风险：你无法验证第三方主机的运营者。历史上有假冒 KMS 服务捆绑恶意软件、收集内网信息、甚至投递勒索程序的案例。
  • 稳定性风险：公共主机随时关停或被封，激活 180 天后无法续期，系统回到未激活状态、功能受限。
  • "正版"状态存疑：此类激活不被微软认可为合法授权，无法获得正常支持与更新保障。
⚠️ 因此本页刻意不罗列任何公共 KMS 服务器清单——这类清单只会在法律与安全上把使用者推向风险。
✅ 如需使用 KMS 激活，请通过你方批量许可（VLSC）获取 CSVLK 自建 KMS 主机；或向组织 IT 管理员索取授权的内网 KMS 主机地址（客户端经内部 DNS _vlmcs._tcp 自动发现），勿自行联网寻找来路不明的公共 KMS 服务。
